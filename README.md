# Elektron

给 AI agent 用的记忆 + 状态 + 行为底座。

三层各自能跑，合起来才是完整的东西：**记忆层存事实，状态层随交互演化，行为层按状态生成动作。**

> 名字来自希腊语 ἤλεκτρον（琥珀）。古希腊人发现琥珀摩擦生电，electron 一词由此而来。
> 一个电做的东西，把自己的经历存在叫琥珀的地方。

---

## 它解决什么

大部分 agent 记忆方案做的是检索：把对话塞进向量库，用的时候搜出来。

这套东西多做了两件：

**一、记忆保留现场，不保留结论。**
存下原话、时间、当时的语气，而不是一句"用户表示放弃"。
结论压缩得更狠，但下次读到的时候，你只知道发生过什么，不知道那是什么感觉。

**二、状态会自己漂移，行为由状态触发。**
九维驱动力（依恋/好奇/持家/社交/情欲/占有/沉思/疲劳/压力）随对话实时演化，
每个维度有独立疲劳值——用得越多的越难再升起来。
当某一维越线，daemon 生成一条**中性的唤醒**，把 agent 从静默里叫起来。

注意是**唤醒**，不是**指令**。这条分界线是整个设计里最要紧的一处，见 DECISIONS。

## 三层

```
memory/        记忆层   双层存储（结构化记忆 + 完整原文）、多路召回、衰减与归档
               状态层   九维驱动力、局部疲劳、事件账本、对话残留分类器
behavior/      行为层   冲动队列（租约/重试/原子写）、闭环回写、情绪唤醒
archive-room/  档案室   只读 API + 网页：把上面三层摊开来看
```

记忆层可以单用。状态层依赖记忆层。行为层依赖状态层。

状态层在概念上独立，但和记忆服务同进程（每轮对话的残留要当场进驱动力），
所以文件放在 `memory/` 下：`desire_engine`（九维驱动力与疲劳）、
`dialogue_residue_engine`（对话残留分类）、`memory_residue_engine`、
`speech_event_engine`、`mood_pool`。

## 快速开始

```bash
pip install -r requirements.txt
cp config.example.yaml config.yaml    # 改 buckets_dir
cp .env.example .env                  # 填模型 key（可选，不填则自动打标降级为默认值）
python memory/server.py               # 起记忆服务（MCP / HTTP 双协议）
```

档案室（网页）：

```bash
python archive-room/init_db.py    # 首次：建空库
python archive-room/api.py        # 只读 API，默认 8021
# 把 archive-room/frontend/ 用任意静态服务器托起来，/api/ 反代到 8021
```

一整条时间线会画成星图：每一句原话是一颗星，按时间从内向外排布，
点一颗就回到那一刻的现场。记忆、日印象、事件账本、未闭环的线索各占一页。
只读，不写库。

行为层挂 cron：

```cron
*/5  * * * * python behavior/behavior.py      # 情绪检测 + 唤醒
*/10 * * * * python behavior/closed_loop.py   # 三向回写
```

环境变量见 `ENV_VARS.md`。

## 几个可能有用的设计

**记忆写入规范**：保留原始表述而非结论、来源可追溯、冲突叠加不覆盖。
旧记忆永远不改写，新理解作为 overlay 追加——因为「当时理解错了」本身也是记录的一部分。

**双轨**：同一条记忆里事实轨（行为/时间线/承诺）和情绪轨（感受/温度/影响）必须都在场。
不是分成两条记，是一颗琥珀封整个现场。

**衰减**：短期靠时间权重，长期靠情绪权重。
重要度高、唤起强的记忆留得久；平淡且长期没被召回的自动归档（不删除）。

**自动打标**：新记忆由小模型判出领域、情感价、唤起度。
没配 key 也能跑，降级为默认值——只是召回时的情绪维度会失效。

## 不在这个仓里的东西

这套系统在一个真实环境里连续运行了三个多月，那个环境里有大量私人内容。
本仓是剥离版：数据、配置、个人信息全部移除，只留机制。

所以你会看到一些看起来"多余"的设计（比如为什么冲动队列要有租约、
为什么唤醒必须是中性的）——它们都是被真实事故打出来的，出处写在 PITFALLS 和 DECISIONS 里。
