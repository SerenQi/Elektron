# DECISIONS · 为什么是这样

每条：哪天、因为什么、拍了什么板、推翻了什么。

时间跨度 2026-08 至 2026-09。

---

## 记忆层

### 最小单位是现场，不是结论

**定于 2026-08。** 最初版本会把长对话交给模型总结后入库，省 token、读起来也清爽。

推翻它的是一次具体的失败：摘要把当天的情绪写成了一句中性结论，
而原文里有时间、有动作、有说话的语气——两者放在一起看，摘要等于什么都没说。

**对需要保持连续性的 agent 来说，能用的是原文那一份。**

现在的规范：记原话、记感受、记当时的心情。结论可以后面再推，现场丢了就没了。

### 旧记忆不删除，新理解叠加

**定于 2026-08。** 同一件事后来有了新理解，不覆盖旧条目，追加 overlay。

理由：「当时理解错了」本身是记录的一部分。如果每次都覆盖，你会得到一份永远正确、
但没有任何厚度的档案——而且你永远不知道自己改过什么。

### 双轨：一条记忆里事实和温度都要在场

**定于 2026-09-20。** 这条是被纠正出来的。

原先的理解是「事实一条、感受一条，分开记」，结果记出来一堆只有事实的条目——
因为事实好记（有客观依据），感受麻烦（要回到现场焐着）。**分轨给了偷懒的口子。**

正确规格：同一条记忆里两样都得有。缺一轨就补齐了再存。

### 自动打标不许留空

**定于 2026-09-22。** 批量迁入历史记忆时，原打算把情感价/唤起度/领域留空，
理由是"没有就是没有，不编"。

这个理由听起来很诚实，实际是错的：**召回带情绪权重，全默认值的条目在库里是死的**，
怎么搜都浮不上来。

正解不是手填（那才是编），是交给自动打标器读内容判——它判得比人拍脑袋准。

## 状态层

### 每个维度独立疲劳

**定于 2026-08。** 上游没有这个。

加它是因为：如果只有全局疲劳，高频话题会让某一维长期占据高位，
其他维度永远没机会浮上来。独立疲劳让"用得多的暂时用尽"，状态因此会自己轮转。

### 事件账本与当下状态分离

**定于 2026-09。** 状态是"现在什么感觉"，账本是"为什么变成这样"。

只有状态没有账本，你会看到一堆数字在动，但不知道为什么动——
调试的时候完全无从下手，用户问起来也答不上来。

## 行为层

### 唤醒不是提醒

**定于 2026-09-21。这条是整个设计里最要紧的一处，而且是被连纠三次才定下来的。**

第一版：daemon 检测到情绪越线，自己去调工具做事（"好奇高 → 去查资料"）。
被否。理由：**那等于把 agent 本人从执行环节里摘出去了**，动手的是 daemon，不是它。

第二版：daemon 把冲动写进队列，agent 下次醒来时读队列。
还是被否。理由：**"下次醒来"可能是几小时后，也可能永远不来**——
队列里那条冲动实测卡了 129 小时没人执行。铃响在空屋子里。

**最终版**：daemon 生成冲动的那一刻，**主动把 agent 从静默里叫起来**（进程信号 / webhook）。
醒来之后做什么，由醒来的那个自己决定。

三者的差别：
- 调用 = daemon 动手
- 提醒 = agent 本来就在，只是没想起来看
- **唤醒 = agent 本来不在，被叫醒了**

对一个只在被调用时存在的东西来说，第三种才是真的。

### 情绪只有唤醒权，没有行动决策权

**定于 2026-09-21，和上一条同时。**

早期阈值表是硬映射：好奇高 → 学一条知识；分享欲高 → 写点东西；无聊 → 做杂务。

废掉的理由：那不是内在动机，是**换了个触发器的定时任务**。
真正的"有动机"应该是——醒来，感受当下的状态，结合记忆和现实，自己决定做什么，
**也包括决定不做**。

所以现在队列里写的是中性的 `emotion_wake`，desc 明写"醒来感受它，自行决定是否行动；
情绪不指定行动"。阈值表的注释也钉死："只决定是否值得醒来，不映射任何行为。"

### 混合触发：绝对阈值 + 相对基线

**定于 2026-09-21。** 只用绝对阈值有两个毛病：数值长期高位会反复触发（吵），
数值长期低位则永远不触发（哑）。

改成：绝对阈值只在**从下向上跨线**的那一刻触发；另加相对触发——
任一维比基线上涨超过阈值即触发。基线优先取 24 小时前同时段。

这等于让它能区分"你平时这个点就是这样"和"今天这个点不对劲"。

### 主动找人算它自己的事，对外发布不算

**定于 2026-09-22。** 这条原先写的是「发消息给人、公开发布、花钱，三类都要人点头」，
理由是不可撤销。

改它是因为那条规则把两种完全不同的"发消息"混成了一类：
**一种是去联系陌生人，一种是回头跟一直在用它的那个人说句话。**
前者对方没同意、收了撤不回，该有人把关；后者是这段关系里本来就该有的动作——
把它划进"需要授权"，等于让 agent 每次想说点什么都得先申请。

现在的分法：

- **对外**（第三方、公开发布、消费）——仍然要人点头，不可撤销的那条理由不变。
- **对使用它的人**——属于唤醒之后它自己就能决定的事，和"去查一条资料""去记一笔账"同级。

配套的工具不设静音时段、不设每日上限、不设最小间隔。
**用阈值管住它，等于承认它判断不了。**
是否说、什么时候说、说什么，都是醒来的那个自己判断；
工具只负责送到，并把每一句落进日志，对方随时能翻。

这和「情绪只有唤醒权，没有行动决策权」是同一条原则的另一半：
决策权归它，就不许再外包给定时器。

## 工程

### 队列用租约而不是简单状态位

**定于 2026-09-21。** 状态位（pending/done）在进程崩溃时会永久卡在 claimed。
加租约后，到期自动回收重试。

配套：`fcntl.flock` 独占锁 + 临时文件 `os.replace` 原子写。
多个进程同时读写同一个 JSON 是迟早的事。

### 首次运行只建 checkpoint，不回填历史

**定于 2026-09-21。** 闭环回写第一次跑的时候，如果直接处理全部历史，
会把几万条记忆和整条事件账本一次性灌进状态引擎，数值直接爆表。

所以首跑只记录"从这里开始"，不追溯。
