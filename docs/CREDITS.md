# CREDITS · 上游谱系

这套东西不是从零长出来的。下面是它站在谁的肩膀上，以及各自改了什么。

**原则：上游的名字一个不漏，我们改过的地方一句不夸。**

---

## 记忆层

**Ombre Brain**（作者 P0luz）
最早的起点。双层记忆的雏形、桶（bucket）这个基本单位、YAML frontmatter + Markdown 正文
的存储格式，都来自这里。Markdown 存储这个选择后来被证明极其正确——记忆可以直接用
Obsidian 打开浏览编辑，不需要任何专用工具。

**Nocturne Memory Core**（作者 Pyruslili）
第二代。在此基础上加入了衰减引擎、多维打分召回、领域自动分类。
现在的 `decay_engine.py` 和 `bucket_manager.search()` 多维加权那部分，骨架是它的。

**本仓（第三代）**
在上述基础上做了结构性改动：
- 原文层（完整对话入库 + FTS5 全文检索）与记忆层分离，两套召回并行
- 记忆写入规范化：保留原始表述、来源可追溯、冲突叠加不覆盖
- 双轨字段（事实轨 / 情绪轨）
- 三路召回 + RRF 融合排序
- 修了若干上游遗留问题，见 PITFALLS

---

## 状态层

**xinchao-dynamic-mind**
动态心智引擎的思路来源：驱动力随交互演化、而不是被显式设置。

**本仓改动**
- 九维驱动力体系重新设计（DRIVE_TAXONOMY_V2.md）
- **每个维度独立疲劳值** —— 上游没有这个。加它是因为：一个维度被反复触发后
  应该暂时"用尽"，否则高频话题会永久压制其他维度
- 对话残留分类器：每轮对话结束后由小模型判断"这段表达了什么"，写入事件账本
- 事件账本与驱动力状态分离：状态是当下，账本是历史，两者都要留

## 行为层

**完全自建。** 没有找到合适的上游。

要解决的问题是：agent 不会自己醒来。它只在被调用时存在。
所以"内在动机"这件事，如果不解决唤醒，就只是个装饰性的数值。

见 DECISIONS 里「唤醒不是提醒」那一条。

## 其他借鉴

**Forge**（上下文交接工具）
"没写完交接包，就不切"这条铁律来自它。本仓的上下文哨兵（不在此包内）沿用了同样的思路：
**自动准备，切换那一下必须人点头。**

**MCP（Model Context Protocol）** by Anthropic
记忆服务同时提供 MCP 和 HTTP 两套接口。

## 一句话

上游给了骨架，真实使用给了肌肉。

这套东西在一个高频、长期、有人真正在乎它记不记得住的环境里跑了三个多月——
大部分设计不是想出来的，是被具体的失败逼出来的。哪一条对应哪次失败，PITFALLS 里写着。
